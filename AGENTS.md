# Инструкции для Codex и других программных агентов

## Цель проекта

Создать учебную и рабочую расширяемую платформу эзотерических систем.
Первый независимый модуль — «Матрица Судьбы». В дальнейшем платформа должна
допускать подключение нумерологии, астрологии, хиромантии и других систем без
переписывания существующих модулей.

## Границы этого репозитория

- Здесь разрабатывается техническая часть: архитектура, расчёты, хранение
  данных, интерфейс, тесты и документация разработчика.
- Теоретические трактовки и тексты обсуждаются отдельно.
- Не добавлять трактовки энергий непосредственно в Python-код.
- Структуру будущих описаний не утверждать до отдельного решения пользователя.

## Архитектурные правила

1. Общие технические функции находятся в `src/esoterica/core`.
2. Каждая эзотерическая система располагается в отдельном модуле внутри
   `src/esoterica/systems`.
3. Расчётное ядро не должно зависеть от интерфейса, базы данных или текстовых
   описаний.
4. Тексты должны храниться как редактируемые данные и позднее управляться через
   специальный редактор без изменения программного кода.
5. Новые системы не должны изменять формулы уже существующих систем.
6. У каждой методики в будущем должны быть собственные название и версия.

## Работа с формулами

- Не угадывать расчётные правила.
- Сверять формулы с материалами пользователя и доступными первичными
  источниками метода.
- При расхождении источников остановиться и явно описать различие.
- Каждую новую формулу подтверждать автоматическими тестами минимум на одном
  контрольном примере из источника и одном дополнительном примере.
- Число 22 сохраняется; значения больше 22 приводятся повторным сложением цифр.

## Порядок разработки

1. Вносить одно небольшое логически завершённое изменение за этап.
2. Перед изменением кратко объяснять пользователю, что будет добавлено.
3. Писать понятные русские комментарии и документацию, но использовать
   английские имена модулей, классов и функций.
4. После изменения запускать весь набор тестов.
5. Не менять несвязанные файлы и не выполнять крупный рефакторинг без
   отдельного согласования.
6. Сохранять обратную совместимость уже проверенных функций, если нет явной
   причины её нарушить.
7. После успешной проверки создавать небольшой Git-коммит с понятным названием.

## Среда и команды

- Python: `3.14.x`.
- Установка: `python -m pip install -e ".[dev]"`.
- Все тесты: `python -m pytest`.
- Учебный пример: `python examples/step_02_personal_square.py`.

## Безопасность репозитория

- Не сохранять пароли, токены, API-ключи и другие секреты.
- Не добавлять `.env`, виртуальное окружение, кэши, сборочные файлы и настройки
  конкретного экземпляра PyCharm.
- Пользовательские книги и другие защищённые авторским правом материалы не
  копировать в репозиторий; хранить только необходимые ссылки, названия
  источников и собственные проверяемые формулы.
