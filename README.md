# Esoterica Platform

Учебный и рабочий проект расширяемой платформы эзотерических систем.

Первый подключаемый модуль — «Матрица Судьбы». На первом этапе мы создаём
только расчётное ядро. Текстовые трактовки будут храниться отдельно от кода и
подключаться позднее через базу данных и редактор знаний.

## Выполненные этапы

### Этап 1. Диапазон энергий

В проект добавлено одно общее правило: приведение положительного числа к
диапазону энергий от 1 до 22.

Примеры:

- `22 -> 22`;
- `29 -> 11`;
- `48 -> 12`;
- `1986 -> 24 -> 6`.

### Этап 2. Личный квадрат

По дате рождения рассчитываются пять базовых точек:

1. левая — энергия дня рождения;
2. верхняя — энергия месяца рождения;
3. правая — энергия года рождения;
4. нижняя — сумма левой, верхней и правой точек;
5. центральная — сумма четырёх вершин.

Контрольный пример `23.01.1987`:

```text
левая = 5, верхняя = 1, правая = 7, нижняя = 13, центр = 8
```

Пример `04.05.1986`:

```text
левая = 4, верхняя = 5, правая = 6, нижняя = 15, центр = 3
```

### Этап 3. Ввод даты рождения

Функция `parse_birth_date` преобразует пользовательский текст формата
`ДД.ММ.ГГГГ` в проверенную календарную дату. Она отклоняет другой формат и
несуществующие даты, например `31.02.1986`.

```python
from esoterica.core import parse_birth_date

birth_date = parse_birth_date("04.05.1986")
```

## Структура

## Запуск проверок

Из корня проекта:

```powershell
py -3.14 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
python -m pytest
```

Ожидаемый результат: все тесты завершатся успешно.

## Архитектурные правила

1. Расчётные формулы не содержат текстовых трактовок.
2. Каждый новый метод добавляется отдельным модулем в `systems`.
3. Общие технические правила находятся в `core`.
4. Любая формула подтверждается тестами на контрольных примерах.
5. Описания будут изменяться через данные, без правки Python-кода.

Подробные рабочие инструкции для Codex и других программных агентов находятся
в файле `AGENTS.md`.

## Работа через Git и Codex

После создания удалённого репозитория основным источником проекта становится
GitHub, а не ZIP-архив.

Рекомендуемый цикл одного небольшого этапа:

1. получить последние изменения командой `git pull`;
2. внести и проверить одно изменение;
3. запустить `python -m pytest`;
4. создать Git-коммит;
5. отправить его командой `git push`.

Файлы виртуального окружения, кэши, секреты и локальные настройки PyCharm
исключены из Git через `.gitignore`.
